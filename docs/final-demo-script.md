# GrievX Campus — Final Demonstration Script

## Demonstration order

1. **Student sign-in** — register or sign in as a student and show the student home screen.
2. **Submit a complaint** — enter a title, description and manual campus location; attach an optional image.
3. **Duplicate review** — submit a similar complaint and show the possible-duplicate warning. Demonstrate both opening the existing issue and choosing the explicit submit-anyway option for a genuinely different issue.
4. **ML result** — show the category, priority and department recommendation when the inference service is configured. Explain that low-confidence routing is sent for manual review.
5. **Community support** — show how a student can upvote an existing complaint instead of creating a second ticket.
6. **Admin sign-in** — sign in with an administrator account and show the complaint queue.
7. **Complaint handling** — open a complaint, inspect evidence and history, assign a department/staff member, and update its status.
8. **Notifications** — return to the student view and show the complaint status notification/timeline.
9. **Analytics** — show KPI totals and category, priority, department and lifecycle breakdowns; export the CSV report.
10. **Campus operations** — show the manual-location heatmap and explain that GPS coordinates are not collected.

## Presentation reminders

- Use demo accounts and non-sensitive sample complaints only.
- Do not show secret keys, database credentials or private provider dashboards.
- Explain that duplicate detection is an application feature, not a fourth ML model.
- Do not claim performance metrics or test results unless they have been measured in the final test phase.
- Keep one backup demo account available in case a session expires.
